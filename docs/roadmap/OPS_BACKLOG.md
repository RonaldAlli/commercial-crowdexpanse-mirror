# Operational Backlog

Standalone operational fixes recorded for scheduling as their own changes. These are **not**
implemented here and are **not** part of any business-evolution initiative (e.g. BE-3). Each is a
distinct ops task with its own branch, gate, and prod-verification when picked up.

Opened alongside the BE-2 governance operational tooling (`chore/governance-operational-tooling`),
2026-07-28.

Relates to [[crowdexpanse-next-ownership]]. |
| OPS-7 | Gitea PR-helper defects (`/home/deploy/bin`) | Surfaced during the first autonomous PR flow (advisory-acceptance merge, PR #13). Two defects block/muddy the helpers. | **(a)** `gitea-pr-merge` preflight and `gitea-pr-state --head` run `python3 - <<'PY' … PY <<<"$json"` — the here-string overrides the heredoc, so Python executes the PR **JSON as a script** and dies with `NameError: name 'true' is not defined`. Fix: feed JSON via a pipe (`printf '%s' "$json" \| python3 - args`), not a second stdin redirect. **(b)** Cosmetic: the final `json_pp` (`python3 -m json.tool`) fails on Gitea's **empty merge-response body** (`Expecting value: line 1 column 1`) even though the merge succeeds — guard for empty body. | OPS-8 | Token-exposure handling + rotation process | A write-scoped token was exposed when `bash -x` traced a token-bearing `curl`; a first rotation replaced only the **write** token while the exposed **read** token stayed active (HTTP 200) until separately revoked. | Process rules: **(1)** never run `-x`/verbose on commands that carry a token; **(2)** on any exposure, revoke the **specific** exposed token and verify the **old value → 401** AND the **new value → 200**, for **both** read and write; **(3)** the helpers resolve `GITEA_READ_TOKEN`/`GITEA_TOKEN` and `GITEA_WRITE_TOKEN` **independently** — rotating one does not rotate the other. Fold into `docs/runbooks/GITEA_API_ACCESS_FOR_CLAUDE.md` rotation procedure. |
